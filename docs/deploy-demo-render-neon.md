# Deploy Maekel API for demo / QA (Render + Neon)

Free-tier path for sharing a working backend with testers. Not production HA.

## What you get

- **Neon** — free managed Postgres (create 6 DBs)
- **Render** — one free web service running identity + market + food + ride + chat + games + gateway
- Flutter points at the Render HTTPS URL via `--dart-define`

**Tradeoffs:** free Render services sleep after ~15 minutes idle (first request can take ~30–60s). Demo start runs all services in **one Node process** to fit the 512MB free plan. If it still OOMs, bump to Render Starter (~$7/mo).

---

## 1. Neon Postgres

1. Create an account at [neon.tech](https://neon.tech) → new project (region close to you).
2. Open **SQL Editor** and run (or paste from `backend/scripts/create-neon-dbs.sql`):

```sql
CREATE DATABASE maekel_identity;
CREATE DATABASE maekel_market;
CREATE DATABASE maekel_food;
CREATE DATABASE maekel_ride;
CREATE DATABASE maekel_chat;
CREATE DATABASE maekel_games;
CREATE DATABASE maekel_events;
```

3. From Neon **Connection details**, note:
   - Host (e.g. `ep-….aws.neon.tech`)
   - User
   - Password
   - Port `5432`

Use the **pooled** host if Neon shows one (often `-pooler` in the hostname).

---

## 2. Render web service

### Option A — Blueprint (repo has `render.yaml`)

1. Push this repo to GitHub.
2. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint** → select the repo.
3. After the `maekel-api` service is created, open **Environment** and set:

| Key | Value |
|-----|--------|
| `POSTGRES_HOST` | Neon host |
| `POSTGRES_USER` | Neon user |
| `POSTGRES_PASSWORD` | Neon password |
| `POSTGRES_PORT` | `5432` |
| `POSTGRES_SSL` | `true` |
| `ADMIN_PHONES` | Your admin E.164 phone(s), comma-separated — e.g. `+251911234567` |

`JWT_SECRET` is auto-generated by the blueprint.

**Admins:** phones in `ADMIN_PHONES` become `platform_admin` + `market_moderator` on OTP login. Those accounts can open **Staff** in the app and grant `market_moderator` to other phones (those people must sign out and OTP again). Normal users no longer get ops access.

4. Deploy / wait for **Live**. Public URL looks like:

`https://maekel-api.onrender.com`

### Option B — Manual web service

- **Root directory:** `backend`
- **Build:** `npm ci && npm run build -w @maekel/shared`
- **Start:** `npm run start:demo`
- Same env vars as above, plus internal URLs:

```text
IDENTITY_URL=http://127.0.0.1:3001
MARKET_URL=http://127.0.0.1:3002
FOOD_URL=http://127.0.0.1:3003
RIDE_URL=http://127.0.0.1:3004
CHAT_URL=http://127.0.0.1:3005
GAMES_URL=http://127.0.0.1:3006
MOCK_OTP_CODE=123456
```

Health check path: `/healthz`

```powershell
curl https://YOUR-SERVICE.onrender.com/healthz
curl https://YOUR-SERVICE.onrender.com/
curl https://YOUR-SERVICE.onrender.com/v1/food/merchants
```

OTP (same as local):

```http
POST /v1/auth/otp/request
{ "phone": "911234567" }

POST /v1/auth/otp/verify
{ "phone": "911234567", "code": "123456" }
```

## 4. Point the Flutter app at Render

```powershell
flutter run --dart-define=API_BASE_URL=https://YOUR-SERVICE.onrender.com
```

For a release APK used in QA:

```powershell
flutter build apk --dart-define=API_BASE_URL=https://YOUR-SERVICE.onrender.com
```

Without `--dart-define`, the app still talks to local `10.0.2.2:8080` / `127.0.0.1:8080`.

---

## 5. QA tips

- First request after idle may be slow (cold start) — hit `/healthz` once before a demo.
- Tables/seeds are created automatically on service boot (migrate + seed).
- If deploy crashes with out-of-memory, upgrade that one web service to **Starter**.
- Rotate `JWT_SECRET` / DB password after public demos if the URL was shared widely.
